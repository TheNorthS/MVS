# 实施决策记录

## 原生命令扩展（2026-11-23）

用户明确把原生 Linux、Windows、macOS 命令纳入项目范围，优先于原始 v1.0 规范中“不暴露
宿主机命令”的定位。新增 `/os` 与 `transport: native`，保留严格 DSL，不启用自由 Shell。
管理员配置按平台指定绝对程序、固定工作目录、argv 字面项/参数引用、Schema、编码和环境引用。
动态值不作字符串格式化；不接受用户的程序路径、Shell 源码或隐式批处理。

复用现有 ServerConfig/ToolDescriptor/Policy 的调用契约，新增 backend 区分和专用原生指标；
原生命令不伪装成实际发生的 MCP 调用。非零退出码保留结果与原始状态，管道错误短路。
参数化路径可按管理员根目录约束，但仍不构成 OS 沙箱或防止文件系统竞态。

Windows 采用 CREATE_SUSPENDED + Job 分配后恢复线程，Job 关闭清理后代；POSIX 采用
独立进程组与 SIGKILL。运行代码捕捉 TimeoutError 必须早于 OSError（前者是后者子类）。
超限或取消后需要排空已终止进程的管道，否则 asyncio.wait 可能被剩余缓冲阻塞。
通过实际测试修复了上述错误，并使用固定系统程序和 PowerShell 脚本验证。

## 阶段 0：原型审查（2026-11-14）

初始工作区只有用户提供的实施规范，没有 MVP、ZIP、源码、依赖清单、测试或 Git 提交。
因此没有可直接复用的原型，也没有可机械迁移的 v1 代码，项目从 `src/` 包结构开始建立。

SDK 边界：只有 `src/mvs/infrastructure/mcp/` 导入官方 MCP SDK，演示入口委托给该层。
统一使用 `Client`、`MCPServer`、`input_schema`、`structured_content`、`is_error`、
`next_cursor` 等 v2 接口。协议协商由 SDK 负责，不手写 `initialize` 握手。
具体依赖版本记录在 `uv.lock` 中。

已核对的官方资料：

- [v1 到 v2 迁移指南](https://py.sdk.modelcontextprotocol.io/migration/)
- [客户端文档](https://py.sdk.modelcontextprotocol.io/client/)

本机有 Python 3.12，系统默认 Python 为 3.11，本项目没有使用默认解释器。
P0 不需要 Redis、数据库服务或其他生产基础设施。

实际验证版本为 mcp 2.3.0、协议 2026-07-28、Python 3.12.6。
阶段 0 的 3 项测试通过，Ruff 和 mypy 通过。Windows 沙箱最初拒绝 stdio 命名管道访问，
因此真实集成测试在获得授权后于沙箱外运行并通过。

## 阶段 1：解析器与抽象语法树

确定性白名单词法器把引号内的控制符保留为字面数据，拒绝未加引号的展开语法。
RawOption 保留选项顺序和源码位置；比较 AST 语义是否相等时忽略源码位置。
缺失参数值交给 Schema 适配器处理，使省略值的标志只适用于明确声明为布尔类型的字段。
测试发现并修正了终止符 `--` 的错误分类。38 项测试通过，Ruff 和 mypy 通过。

## 阶段 2：注册表、虚拟文件系统与会话

SDK 上下文由专门任务持有，使 AnyIO 取消作用域在同一任务中进入和退出。
发现过程有分页上限，显式设置安装版本 2.3.0 所需的 `cache_mode="refresh"`。
注册表采用写时复制，新字典构建完成后发布；读取方拿到与内部数据分离的快照。

不能直接用作路径的工具名使用保留前缀 `~` 和 URL 安全的 base64 编码；普通点号、横线
和下划线保持不变。发现失败会把相应服务器标记为离线。46 项测试通过，包含真实注册表
刷新和生命周期验证，随后补充分页测试。

## 阶段 3：参数适配与权限策略

Schema 类型转换保持确定性；联合类型和组合约束使用 `--params-json`，避免猜测。
默认值只用于文档提示。重复 JSON 键、非有限浮点数、过大整数、远程或动态引用、过深
嵌套都被拒绝。最终参数按原 Schema 方言验证。

权限策略同时要求可信主体/租户的服务器授权和管理员工具白名单。服务器注解不能授权。
72 项测试通过，Ruff 和 mypy 通过。

## 阶段 4：执行器、服务与命令行

ShellService 负责完整调用顺序和响应契约。会话锁串行处理状态变更，执行器信号量限制
每台服务器的并发。获得信号量后再检查注册表版本。MVS 不自动重试调用，超时表示
`TIMEOUT_UNCERTAIN`。协议协商由 SDK 内部处理。

审计不保留原始命令和参数值，只记录标识、字节数、版本、耗时及错误。CLI 使用 argparse
和 `input()`，不会调用操作系统 Shell。非文本内容以私有数据和不透明引用保存，持久化
存储与读取在阶段 5 接入。增加并发和安全测试前，73 项测试通过，规范第 16 节的真实
演示链也已通过。

P0 最终结果：77 项测试通过，语句覆盖率 87%，Ruff 和 mypy 通过。
实际安装的 CLI 返回标准输出 `30` 和数据 `{"result": 30}`。后续运行增加了分支统计。

## 阶段 5：结果存储与管道

SQLite 元数据和对象文件实现 UUID4 标识、所有者/租户检查、TTL、内容哈希，以及单条
结果和总存储配额。管道在既有词法器中增加显式管道标记，引号内的管道符仍为数据。
有界纯转换不会额外发出 MCP 调用。资源、资源模板和提示词采用独立目录与可信白名单。

87 项测试通过，包含真实管道、结果读取、资源、资源模板和提示词；Ruff 和 mypy 通过。
`pipelines=False` 用于兼容测试，保留 P0 拒绝管道的行为。每阶段 CPU 时间的硬性限制
尚未落实，不能将功能通过等同于该项安全要求已完成。

## 阶段 6：API 与工程增强

可选 FastAPI 使用管理员配置的 Bearer 令牌映射，拒绝请求体指定身份，并按身份隔离
客户端和注册表。SDK 2.3.0 的 HTTP 实现使用 httpx2，与 FastAPI 测试使用的 httpx 不同。
发出请求前检查来源与 IP。列表刷新使用可移植的 TTL 兜底，而不混用新旧通知接口。
恢复发现不会重放工具调用。OTel 和 Prometheus 属于可选 API 依赖。

真实 HTTP 和 API 测试使通过数达到 93。随后，隔离 SDK 1.30.0 环境的两项真实 stdio
双向兼容测试也通过。本地 240 次调用的微基准已经保存；在当时检查点，模型 Token 与
选工具实验、生产化 P2 仍未完成。后续增量结果和当前限制见[验收报告](../reports/validation_report.md)。

## GPT 实验与监控增量（2026-11-14）

用户明确选择 GPT 和 240 组。先探测本机已配置的 Responses 服务，gpt-5.4-mini 虽在
目录中，却不接受请求；gpt-6-astra 实际请求成功并返回用量字段 `usage`。正式实验固定
使用 gpt-6-astra 和低推理强度 `low`。管理员配置只用于读取端点与凭证，不进入报告。
接口为自定义兼容网关，记录返回模型名，但不把它视为独立的供应商身份认证。
6 组冒烟测试全部成功后启动 240 组，失败原样保留，不自动重试。

旧基准的三条链路功能不等价且没有模型参与。新基准统一后端 Schema、权限和结果保存，
由模型自行选择下一次调用。20 种合成业务任务通过加入相似历史工具扩展为 20、50、100、
200 工具规模。真实 MCP 处理函数生成可判分的校验码；模型必须实际调用正确工具、传入
正确参数，并给出正确最终值。

各轮输入、输出、缓存用量独立保存，不把缓存 Token 再加进输入，也不把字节数当 Token。
统计同时提供全样本成功率，以及双方均成功、用量完整的同任务配对比较，并明确列出排除项。

监控采用默认无操作的 `domain.Telemetry`，保持核心运行不依赖 Prometheus。
可选适配器负责请求/工具计数器、耗时直方图、发现刷新、成功写入字节和固定原因的显式
授权拒绝。目录权限过滤不计拒绝；排队前失败不计实际工具调用；存储失败不计写入量。
超时和取消单独标记，在 `finally` 中计数。每个 API 应用拥有独立 CollectorRegistry，
不使用任意用户输入作为高基数标签。API、Shell、执行器追踪片段嵌套，审计关联真实追踪标识。

该阶段115项测试通过，总体覆盖率87%，监控适配器覆盖率100%，属于历史代码验收。

当前模型结果统一引用2026-11-25的0.0.1实验：240个有效任务全部成功，使用1,681,974 Token。
接口502与网络超时排除出能力评分，有效执行的工具选择、参数合法性、参数正确率均为100%。
20/50/100/200工具规模下，MVS相对原生入口Token变化为增加66.6%、减少8.0%、减少34.0%、
减少47.5%，每格20个同任务配对。完整记录见[最新实验报告](../../artifacts/benchmarks/gpt-240-20261125-185218-v0.0.1/report.md)。
